# Contributing to kagami

Thank you for your interest in kagami. We welcome all kinds of contributions, including bug reports, documentation improvements, and feature proposals and implementations.

## Before you start

- For large changes or new features, please open an issue to discuss them before creating a pull request. This helps avoid spending time on work that doesn't fit the project's direction.
- For typo fixes or small bug fixes, you can open a pull request directly without creating an issue.
- This project is maintained by ZUNDA Inc. Reviews and replies may take some time, and we can't guarantee that every pull request will be merged.

## How to submit a pull request

1. Fork the repository and create a branch for your work.
2. Make your changes and make sure CI passes.
3. Open a pull request and describe what you changed and why, following the template.

Before submitting a pull request, please confirm the following:

- You wrote the code yourself. If your employer holds rights to it, you have your employer's permission.

If you realize after submitting that any of the above does not apply, please let us know in a comment on the pull request or in an issue.

If you do not agree to the CLA, please do not submit a pull request. Automated pull requests from bots are not subject to the CLA.

## Reporting vulnerabilities

Please do not report security issues in public issues. Instead, report them privately using "Report a vulnerability" on the repository's Security tab.
